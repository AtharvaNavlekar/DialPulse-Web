# DialPulse Brain

This directory acts as the central source of truth for the DialPulse project.

## Core Files
- `PROJECT-CONTEXT.md`: The overarching product goals and architecture.
- `MARKETING-CONTEXT.md`: Information architecture, messaging strategy, and conversion goals.
- `DESIGN-DNA.md`: Typography, color strategy, and structural guidelines (Material 3 + CRM).
- `BRAND-RULES.md`: Absolute constraints on what NOT to do (Anti-Slop rules).
- `PUBLIC-CLAIMS-REGISTER.md`: Verified claims inventory, classification schema, and truthfulness audit.
- `PRIVACY-POLICY-REQUIREMENTS.md`: Internal privacy requirements specification and technical facts.
- `OPEN-QUESTIONS.md`: Register of unresolved commercial, legal, and operational decisions.
- `DECISIONS.md`: Architectural, procedural, and design decisions log.
- `CHANGELOG.md`: Historical project change log.

## SDLC Governance Standard
- `SDLC.md`: Master 9-stage Software Development Lifecycle operating procedure.
- `SDLC-REQUIREMENTS.md`: Requirements engineering framework and ID taxonomy (`FR`, `NFR`, `SEC`, `PRIV`, `UX`, `SEO`, `OPS`).
- `REQUIREMENTS-BASELINE.md`: Canonical authoritative requirements inventory categorized across Functional, Non-Functional, Security, Privacy, UX, SEO, and Operations.
- `SDLC-TRACEABILITY.md`: Bidirectional requirements traceability matrix linking requirements, design, implementation, and test evidence.
- `SDLC-CHANGE-CONTROL.md`: Formal change control rules, categories, risk matrix, and re-test triggers.
- `SDLC-TEST-PLAN.md`: 13-point master testing strategy, verification reality, and QA matrix.
- `SDLC-RELEASE-CHECKLIST.md`: Release verification gates, deployment steps, smoke tests, and rollback protocol.
- `RISK-REGISTER.md`: Centralized project risk register with qualitative severity ratings, owners, and mitigations.
